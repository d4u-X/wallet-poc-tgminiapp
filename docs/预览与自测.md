# 预览链接与自测指南

## 1. 本地预览（最快）

仓库里 Vite 配置了 `base: '/reactjs-template/'`，本地开发时请使用 **带 base 前缀** 的地址（否则静态资源路径会 404）。

```bash
pnpm install
pnpm dev
```

在浏览器打开：

- **欢迎页（闭环 A 起点）**：  
  [http://localhost:5173/reactjs-template/](http://localhost:5173/reactjs-template/)  
  路由使用 Hash，等价于：`http://localhost:5173/reactjs-template/#/`

- **常用路径（可直接粘贴）**
  - 首页欢迎：`#/`
  - 设密码：`#/onboarding/password`
  - 助记词生成：`#/onboarding/mnemonic/generate`
  - 备份：`#/onboarding/mnemonic/backup`
  - 验证：`#/onboarding/mnemonic/verify?tab=random` 或 `?tab=full`
  - 钱包首页：`#/home`（需先走完流程或 sessionStorage 已有完成标记）
  - 旧版 TMA Demo：`#/demo`

同一局域网手机扫码访问（终端里会打印 `Network` 地址）：

```bash
pnpm dev -- --host
```

把终端里的 `http://<你的局域网IP>:5173/reactjs-template/` 发给手机即可（仍需在同一 Wi‑Fi）。

---

## 2. 构建产物本地预览（接近线上）

```bash
pnpm run build
pnpm run preview
```

默认预览一般为 **`http://localhost:4173/reactjs-template/`**（具体端口以终端为准），同样使用 **`#/…`** 访问各路由。

---

## 3. 公网预览链接（给同事 / 产品看）

我无法替你生成“永久固定”的 URL，需要你们任选一种托管方式：

| 方式             | 说明                                                                                                                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **GitHub Pages** | 推送到你们配置了 Pages 的分支后，在仓库 **Settings → Pages** 查看站点 URL。注意：**`vite.config.ts` 里的 `base` 必须与 Pages 路径一致**（例如仓库站点为 `https://组织.github.io/仓库名/`，则 `base` 应为 `'/仓库名/'`，而不是沿用模板里的 `/reactjs-template/`）。 |
| **任意静态托管** | Cloudflare Pages / Vercel / Netlify 等部署 `dist`，并把 **`base`** 改成对应子路径或根路径 `"/"`。                                                                                                                                                                  |

部署后的访问形式一般为：

`https://你的域名/<base 路径>/#/`

## 4. 在 Telegram 里自测（真机）

Telegram Mini App 要求 **HTTPS**。本地 `http://localhost` 无法直接在 Telegram 客户端打开，需要隧道：

1. 本地：`pnpm dev -- --host`
2. 使用 **Cloudflare Tunnel** 或 **ngrok** 等把 `5173` 暴露为 `https://xxxx`
3. 把该 HTTPS 地址配置到 Bot 的 Mini App URL
4. iOS/Android 真机打开 Bot 里的 Mini App 验证 **安全区、返回键、主题**

详细步骤可参考仓库根目录 [README.zh-CN.md](../README.zh-CN.md) 里的「隧道 / 真机调试」章节。

## 5. 自动化自检（开发 / CI）

提交前或怀疑环境问题时在项目根目录执行：

```bash
pnpm lint
pnpm run type-check
pnpm run build
pnpm run format:check   # 可选
```

CI（`.github/workflows/ci.yml`）会对 PR / 推送执行同类检查。

## 6. 功能与界面手测清单（闭环 A）

建议按顺序测一遍，并在 Telegram WebView 里复测重点项。

**欢迎页**

- [ ] 背景、Logo、三条卖点、主/次按钮样式正常
- [ ] 「创建新钱包」进入密码页
- [ ] 「导入已有钱包」出现 Mock 提示
- [ ] 服务条款 / 隐私政策能跳转（`openLink`）
- [ ] 开发模式下底部有「旧版 TMA Demo」入口

**密码页**

- [ ] 少于 8 位提交有错误提示
- [ ] 两次不一致有提示
- [ ] 合法密码可进入助记词生成页

**助记词生成**

- [ ] 默认遮罩 / 模糊，点击后出现 12 词
- [ ] 「下一步」进入备份页

**备份**

- [ ] 12 词顺序与生成页一致
- [ ] 「已备份，开始验证」进入验证页（默认随机 Tab）

**验证**

- [ ] 「随机验证」与「完整验证」Tab 切换正常，URL `tab=` 同步
- [ ] 错误词有误提示；全部正确后进入 `/home`
- [ ] 完成后刷新：`/` 应自动跳到 `#/home`（sessionStorage）

**首页 `/home`**

- [ ] 未完成 onboarding 直接打开 `#/home` 会被重定向到 `#/`
- [ ] 开发模式「重置创建流程」可清空状态回到欢迎页

**回归**

- [ ] `#/demo` 模板页仍可打开（TonConnect 等）
