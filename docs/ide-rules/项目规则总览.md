---

## 1. 技术栈（必须遵守）

- React 18 + TypeScript（strict）
- Vite 6 + `@vitejs/plugin-react-swc`
- Tailwind CSS v4（使用现有的中心 CSS 入口/主题文件，不引入 CSS modules/BEM）
- Telegram Mini App：`@tma.js/sdk-react`
- TON Connect：`@tonconnect/ui-react`（如未使用也不应破坏现有接入）
- 路由：`react-router-dom` v6 + `HashRouter`
- className：`clsx`
- 包管理：`pnpm`

---

## 2. 产品代码与 Demo 代码边界

- 产品页：`src/pages/app/`
- Demo/模板页：`src/pages/demo/` 且仅在 `/demo/*`
- 产品页视觉：必须使用钱包设计系统（`src/styles/wallet-theme.css`），不要使用 Telegram host palette（`--tg-theme-*`）去“凑色”

---

## 3. 设计稿高还原（Figma Fidelity）

- 按“材质层”还原，而不是只堆内容块：背景载体/渐变/蒙层/模糊/描边/阴影/遮罩/纹理/图标资产
- 优先使用 Figma 导出的真实图标/纹理资产；不要用近似手绘替代
- 在抽组件前先把单页做到像（尤其 375px 宽度下）
- 提交需求/改动时应附带 Figma 链接（含 `node-id=`）并说明状态（default/active/empty/error 等）

---

## 4. 钱包流程与当前里程碑

- Onboarding 门禁流程：password → reveal mnemonic → backup → verify → home
- 备份为强制流程（不允许跳过）
- 当前里程碑：高保真 UI + 本地加密金库（IndexedDB + Argon2id + AES-GCM）
- 网络/RPC/交易/广播可先保持 mock，除非明确要求接入真实链上交互
- 不要引入签名/广播/服务端托管逻辑，除非明确要求

---

## 5. 编码与质量规则

- 每个文件优先一个具名导出（避免 default export）
- 使用 `@/` 路径别名，避免深层相对路径
- Props 类型定义与组件放同文件（`type`/`interface`）
- 不使用 `@ts-ignore`
- 不使用 Tailwind `@apply`（需要复用就抽 React 组件）
- `public/` 下的静态资源必须用 `publicUrl(...)` 引用，保证 `base` 可变时不翻车
- 异步必须显式处理错误，不要静默吞异常
- 改动后保持 format/lint/typecheck/build 全绿
- 外链使用共享 `Link` 组件（或安全封装）以同时兼容 Telegram 内与浏览器预览环境
